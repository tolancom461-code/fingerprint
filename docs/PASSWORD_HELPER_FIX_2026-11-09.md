# إصلاح إدخال أداة إنشاء كلمة المرور

قبل التعديل كانت الأداة تعرض رسالة عامة لكل أنواع الفشل، وكان قارئ الأحرف اليدوي قد يترك أجزاء مفاتيح الهروب أو اللصق داخل الإدخال. نجح إدخال صالح في الاختبار السابق؛ لذلك لم ينسب فشل صاحب المشروع إلى سبب بعينه ولم تطلب كلمة مروره.

بعد التعديل تستخدم الأداة قارئ طرفية قياسيًا بخروج صامت ودون تاريخ، وتعرض سببًا محددًا للإدخال الفارغ أو القصير أو الطويل أو متعدد الأسطر أو الإلغاء أو تعذر القراءة. تفك حروف UTF-8 عبر أجزاء stdin بصورة متصلة، وترفض تمرير كلمة المرور كوسيط دون طباعتها.

نجحت اختبارات CLI الأربعة واختبار طرفية تفاعلية بإدخال وهمي ولصق مؤطر. مجموعة المشروع كاملة: 231 من 231. بقي scrypt بصيغته ومعاملاته وسياسة طول كلمة المرور دون تغيير؛ لا يلزم نشر خادم جديد لاستعمال الأداة المحلية المصححة.

يعاد تشغيل:

```powershell
cd C:\Users\mh\Desktop\FINGER\Fingerprint\biometric-system
npm run admin:password-hash
```

تكتب كلمة مرور من 12 إلى 256 حرفًا رغم عدم ظهور الحروف، ثم يضغط Enter. ينسخ سطر الهاش الناتج فقط إلى متغير Railway، وتستخدم كلمة المرور الأصلية عند تسجيل الدخول.
