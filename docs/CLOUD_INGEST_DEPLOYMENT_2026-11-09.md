# تجهيز الاستقبال السحابي والحفظ

## الحالة المثبتة

جهز مدخل `database-ingest` للاستقبال المصادق عليه والحفظ في `fingerprint` مع بوابة عرض محمية. اختبر الحفظ عبر HTTP فعليًا على MySQL محلي جديد، واختبر تشغيل المدخل وقوائمه على TiDB الفعلية بفحص يفرض SELECT/SHOW فقط. **لم يغيّر هذا العمل وضع Railway المنشور أو اتصال الجهاز.**

بقي النشر العام بوضع القراءة إلى حين رفع التحديث وتطبيق ملف Variables الجديد. تجهيز الخادم والقاعدة يختلف عن إثبات اتصال الجهاز الفعلي أو إغلاق المرحلة الأولى.

## ما تغير

- أضيف `src/cloud-ingest.js` وإعداده الصريح `src/config/cloud-ingest.js`، واختيار ثالث في `src/railway.js`. يبقى `demo` الافتراضي، و`database-readonly` السابق صالحًا للرجوع.
- يحتاج `/iclock/` ترويسة آلة `Authorization: Bearer <machine-token>` قبل استدعاء محول الجهاز أو مخزنه. جلسة البوابة والرقم التسلسلي وquery parameters لا تحل محلها. بعد المصادقة يفحص رقم الجهاز في قائمة السماح. لا تسجل الترويسة أو محتوى الحركة في التشخيص.
- يستعمل الكاتب حسابًا جديدًا بمنح جدولية محددة للقراءة وINSERT/UPDATE المطلوبة، دون DELETE أو DDL أو منح عامة. يرفض الحارس root واسم المصدر والدور النشط والمنح الأوسع والمخطط غير الموافق، ويثبت TLS وهوية الخادم والمهل.
- يبدأ هذا الوضع دون اعتماد تلقائي للأحداث النهائية أو توصيل إلى TolanHR. تحفظ raw والحركة canonical، وتظهر في قائمة «الحركات المستلمة» بما فيها غير المرتبط أو المعلق، بدل اختفائها من قائمة الأحداث النهائية.
- تظهر «مستخدمو الأجهزة» أرقام وهويات المستخدمين الآمنة. لا تنقل كلمات مرور الجهاز أو البطاقات أو القوالب الحيوية، ولا ينشئ وصول مستخدم جهاز شخصًا أو عاملًا تلقائيًا. الربط بالأشخاص مستقل.

## قاعدة البيانات والنسخة الاحتياطية

نفذ إجراء التجهيز على `fingerprint` فقط بعد اختبارات ومراجعة مستقلة. حفظت نسخة حديثة للجداول العشرة وDDL وجميع الصفوف بلقطة TiDB ثابتة `2026-11-09 13:38:14.571441` بتوقيت الجلسة، وأعيد فحص الملفات وبصماتها. لم تجر بروفة استعادة جديدة لهذه النسخة؛ بروفتا النقل السابقتان موثقتان في سجل النقل.

أضيف `automatic_finalization_eligible` بقيمة 0 لكل سجلات المعالجة القديمة، وأنشئ الكاتب الجديد ومنح مصفوفتَه فقط. طابقت جميع قيم الأعمدة السابقة وبصماتها قبل الإضافة وبعدها، وبقيت تعريفاتها وفهارسها وعداداتها سليمة. لم يحذف سجل أو يعاد توليد ID أو UUID، ولم تفتح قاعدة `test`.

النسخة محلية خاصة في `verification/cloud-ingest-backup-5W6CVE/`، والتقرير المنقح `verification/cloud-ingest-db-setup-2026-11-09.json`. تحتوي ملفات الصفوف بيانات حقيقية، وهي مستبعدة من Git وحزمة npm وDocker. ملف حساب الكاتب الخاص `.env.ingest-database.tidb` مستبعد كذلك.

توقف الإجراء الأول قبل أي تعديل عند اختلاف قيمة عداد محلي عن العام، وحفظ دليله ونسخته في `verification/cloud-ingest-db-setup-counter-precheck-2026-11-09.json`. أصلحت مقارنة العدادات بناء على مصدر TiDB: [`information_schema` يستخدم المحلي](https://github.com/pingcap/tidb/blob/v8.5.3/pkg/executor/infoschema_reader.go#L250-L274)، بينما [`SHOW CREATE` يستخدم العام](https://github.com/pingcap/tidb/blob/v8.5.3/pkg/executor/show.go#L1268-L1278). بقي انخفاض العام أو فساده سببًا للإيقاف؛ لم تنفذ أوامر إعادة ضبط أو rebase لأي عداد.

## التحقق

- نجح مختبر الاستقبال الجديد 9/9: رفض الطلب قبل أي حفظ دون مصادقة، وحفظ ATTLOG وcanonical، والتكرار، وOPERLOG الآمن، وقوائم البوابة، وتعافي القاعدة وإعادة تشغيل المدخل.
- نجحت اختبارات الحزمة 406/406. تشمل الحارس والمهل والمنح والمعاملات والمصادقة والإعدادات الجديدة وفصل العرض عن الأحداث النهائية، واستمرار وضع القراءة وdemo.
- اختبر المدخل محليًا متصلًا بـTiDB الحقيقية باستخدام الكاتب الجديد وTLS، مع منع أي SQL كتابة داخل أداة التحقق. اجتاز 6/6: الجاهزية والدخول والقوائم الخمس والأعداد و401 للطلب غير المصادق عليه ومطابقة الأعمدة القديمة للجداول العشرة مع النسخة الحديثة. الأعداد: جهاز1، أشخاص5، أحداث نهائية33، سجلات استقبال245، مستخدمو أجهزة129. لم ترسل حركة مصطنعة أو طلب جهاز مصادق عليه إلى TiDB.
- عولج فرق فعلي في TiDB عند ربط LIMIT/OFFSET كمعاملات رقمية: يستعمل القارئ الجديد أعدادًا صحيحة محدودة ومتحققًا منها داخل SQL، بينما يظل البحث parameterized. أضيف اختبارا رفض المدخلات غير الآمنة وعدم استعمال الربط غير المتوافق.

الأدلة المحلية: `verification/cloud-ingest-mysql-verification-2026-11-09.json`، و`cloud-ingest-tidb-runtime-verification-2026-11-09.json`، و`cloud-ingest-all-tests-final.log`، و`cloud-ingest-deployment-env-verification-2026-11-09.json`.

اجتاز التوزيع 272 ملفًا دون ملفات الاعتماد الخاصة التسعة أو النسخ والتقارير أو قيم الأسرار السبعة الفريدة، وبقيت ملفات الأصل109 وTolanHR454 مطابقة للمرجع. لم يكتمل الفحص البصري للمتصفح: IAB غير متاح، وانتهت مهلة إتاحة Chrome قبل فتح الصفحة؛ أغلق خادم QA المصطنع، ولم تعتمد تخطيطات الكمبيوتر أو الهاتف أو تلتقط صور. التقرير `verification/cloud-ingest-ui-visual-qa-2026-11-09.json` يثبت هذا القيد، ولا تستبدل به الفحوص الوظيفية الناجحة.

## الرفع والنشر

1. ارفع تحديثات مصدر `biometric-system` كاملة، بما فيها الملفات الجديدة. لا ترفع ملفات `.env` الخاصة أو `verification`. المثال العام `.env.ingest.example` فارغ من الأسرار.
2. ملف `.env.railway.ingest.complete.tidb` الخاص جاهز كبديل كامل لقائمة Variables: 34 متغيرًا دون placeholders أو مراجع خارجية. يحفظ بيانات دخول البوابة السابقة، ويضم الكاتب وقائمة الجهاز ومفتاح قناة الاستقبال. لا يحتاج `DATABASE_URL` القديم بحساب root، لذلك لا يتضمنه.
3. في Railway احتفظ بـStart Command `node src/railway.js` وHealthcheck `/ready` والمنفذ8080 ونسخة واحدة، ثم طبق Variables وانشر. ملف `deploy/railway-ingest.settings.json` مرجع يدوي وليس إعدادًا يطبقه Railway تلقائيًا.
4. بعد النشر تحقق من `/ready` وأنه يعيد `mode=database-ingest`، ومن الدخول وظهور قائمتي الحركات المستلمة ومستخدمي الأجهزة بالأعداد الحالية. الطلب إلى ADMS دون مفتاح يجب أن يرفض بـ401 دون تغيير بيانات.

## ربط الجهاز والخطوة اللاحقة

**لا توجه الجهاز إلى النطاق بمجرد نشر هذا الوضع.** هذا المدخل يتطلب تقديم اعتماد القناة؛ لم يثبت أن firmware الحالي يستطيع إرسال ترويسة المصادقة المطلوبة. إذا لم يدعمها، تجهز قناة أو موصل محلي مصادق عليه. لا يتطلب هذا شراء ZKTime، ولا يجعل تفعيل Standalone Communication الجهاز يرسل إلى موقعنا تلقائيًا.

ما زالت طريقة حفظ كامل تاريخ الجهاز غير محسومة بعد عدم ظهور USB وعدم استجابة4370، وصورة صاحب المشروع تثبت أن Standalone Communication معطل. لا يغير هذا الإجراء إعداداته أو يعيد تشغيله. تبقى مصالحة ما بعد اللقطة وحفظ تاريخ الجهاز وحالة التسليم قبل تحويل الإنتاج أو تفعيل الاعتماد النهائي والتوصيل.

للرجوع إلى عرض القراءة: أعد `BIOMETRIC_RAILWAY_MODE=database-readonly` وانشر مع `/ready` ومتغيرات القارئ السابقة الموجودة في الملف الكامل. لا تحذف العمود أو الحساب الجديد أو النسخة الاحتياطية، ولا يحتاج الرجوع كتابة المصدر.
