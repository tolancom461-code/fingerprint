# مطابقة دليل المستخدمين مع الجهاز

## النتيجة المثبتة

في 10 نوفمبر 2026 الساعة 17:48 بتوقيت الرياض طابق دليل المستخدمين الحاليين في `fingerprint` مع **175 معرّفًا وقيم حقول الاسم** كما أعادتها قراءة SDK. فحص اللقطة المحفوظة لاحقًا أكد أن قيمتي `Name` للمعرّفين `1` و`2` فارغتان، وأن القيم الـ173 الأخرى بصيغة Base64. فك Base64 أعاد بيانات تتضمن محارف تحكم بدل الأسماء المقروءة. نوع الترميز الداخلي غير مؤكد. استعملت قراءة SDK إسقاط `user / Pin,Name` فقط، مع مطابقة مجموعة المعرّفات لقراءة Pin المستقلة وثبات العداد قبل وبعد والتحقق من الهوية والفصل. لم تقرأ كلمات مرور أو بطاقات أو قوالب حيوية.

أضيف 9 مستخدمين، وحفظت المعرّفات الداخلية للـ166 المشتركة، وحدّثت الأسماء من الجهاز. أبقيت 7 هويات غير مسجلة حاليًا بالحالة `absent_from_device`؛ بينها هويات لها حركات صحيحة وروابط عمال. الجدول يحوي182صفًا إجمالًا، منها175حاليًا و7تاريخيين. لا تحذف المزامنة هوية تاريخية أو رابط عامل ولا تنشئ عمالًا أو روابط تلقائية.

نفذت المزامنة في معاملة واحدة بعد نسخة متسقة للجداول العشرة واختبار الاستعادة محليًا. أكد الفحص اللاحق بحساب SELECT ثبات محتوى3595حركة و3596استقبال وحالة معالجة و5أشخاص و5روابط هوية وحدث نهائي واحد و410مشكلات اعتماد. أضيف سجل تدقيق واحد وأبقيت السجلات السابقة. لم تتصل العملية بقاعدة `test` أو تغيّر الجهاز.

## سلوك البوابة بعد نشر الكود

- قائمة المستخدمين تعرض الحاليين افتراضيًا:175.
- `GET /api/portal/device-users?roster=current|historical|all` يعرض الحاليين أو التاريخيين أو الجميع، ويظل عدّاد الحاليين مستقلًا عند عرض الجميع.
- عند وجود تاريخ يضاف `historicalDeviceUsers` و`allDeviceUsers` إلى عدادات الملخص، و`rosterCounts` إلى القائمة. عند عدم وجود تاريخ يبقى شكل الرد السابق.
- وصول `USER` صريح يعيد `absent_from_device` إلى `seen` فقط، ويحفظ حالات المستخدمين الأخرى. إعادة `ATTLOG` تاريخية لا تعيد التفعيل تلقائيًا.
- البحث والتصفح والمصادقة وحدود القراءة تبقى مطبقة، والأسماء تعرض كنص.

## التحقق والنشر

اجتاز المشروع453اختبارًا، والقارئ المؤقت58اختبارًا لكل منx64وx86. نجح اختبار MySQL جديد ومعزول لاستعادة النسخة ثم المزامنة والرجوع ثم المزامنة والاستعادة، مع مطابقة المحتوى الأصلي والروابط. تحققت واجهة القراءة الجديدة محليًا من قاعدة TiDB بحساب SELECT:175حاليًا و7تاريخيين و182إجمالًا، وجميع المعرّفات وقيم حقل الاسم مطابقة لخرج SDK المحفوظ.

تحديث القاعدة منفذ. ظهور الفصل بين الحالي والتاريخي في النطاق العام يحتاج رفع الكود المستقل ونشره على Railway. لا حاجة إلى متغيرات جديدة أو تغيير بنية القاعدة أو إعادة إعداد الجهاز. إلى حين نشر الكود قد تعرض النسخة القديمة182لأنها تجمع الحالي والتاريخي.

الأدلة المنقحة محليًا: `verification/user-directory-sync-local-verification.json` و`user-directory-sync-apply-result.json` و`user-directory-sync-postcheck.json`. تحفظ الملفات الفردية والنسخ والمفاتيح داخل `verification` المستبعد من Git والحزمة وDocker.
