# نتيجة تجهيز نشر Railway التجريبي

التاريخ: 8 نوفمبر 2026. الحالة الحالية: وفر صاحب المشروع نطاق Railway واجتاز الفحوص العامة الخمسة عبر HTTPS. نتائج التجهيز المحلي موثقة أدناه؛ سجلات بناء النشر وإعداداته الداخلية لم تراجع.

## قبل التعديل

المشروع المستقل يحتوي كود خدمة البصمة الأصلي واختباراته، دون Dockerfile أو مدخل تجربة سحابية مخصص. أمر التشغيل المحلي يعتمد على إعدادات الخدمة المعتادة، لذلك لا يصلح اختياره للتجربة العامة دون عزل.

## التعديلات المنفذة

- إضافة `Dockerfile` يشغل `node src/railway-staging.js` ويثبت الحزم من lockfile، دون نسخ أسرار أو سجلات أو بيانات إلى الصورة. مستخدم التشغيل هو `node`.
- إضافة مدخل تجربة يقرأ `PORT` قراءة صارمة ويستمع على `0.0.0.0`، ويطبق عزل التجربة قبل تحميل runtime الأصلي.
- فرض تخزين ملفي، ورفض جميع الأجهزة بما فيها قائمة السماح القديمة، وتعطيل الإدارة وAPI وWeb Bridge والتثبيت النهائي. تبقى قاعدة الإنتاج خارج مسار التشغيل.
- عزل مسارات الملفات والمؤشر داخل مجلد `railway-staging` مخصص بدل وراثة مسارات الإنتاج.
- إضافة `start:railway-staging` مع الإبقاء على `npm start` ومدخل التشغيل الأصلي دون تغيير.
- إضافة مثال متغيرات عام، ومرجع إعدادات Railway يدوي، ودليل نشر يوضح root directory والمنفذ وفحص الصحة ونطاق التجربة والتراجع.
- الاعتماد على Docker وإعدادات الخدمة أو IaC بدل `railway.json`؛ الوثائق الحالية للمنصة لا تتيح Config as Code القديم للخدمات الجديدة.

## نتائج التحقق بعد التعديل

- `npm test`: نجح 201 من 201، منها 194 اختبارًا سابقًا و7 اختبارات جديدة. مجموعة حدود الاستقلال الستة جزء من العدد نفسه.
- اختبار عملية فعلية ببيئة إنتاج مزيفة: `/health` يعيد 200 و`OK`، وطلبات جهاز افتراضي ترفض بـ403، ومسارات الإدارة وAPI ترد 404، ولا يحدث اتصال إلى مصيدة DB أو Bridge ولا التقاط لمحتوى حركة أو تغيير لمؤشر الإنتاج المزيف.
- فحص بناء جملة مدخلي JavaScript ناجح.
- فحص `npm pack --dry-run` وحزمة ZIP النهائية: 188 ملفًا، تشمل Dockerfile والمدخل ومرجع الإعدادات وتقرير التجهيز، دون أسرار أو بيانات تشغيل أو node_modules أو أدلة تحقق. ملفات `.env.example` و`.env.railway.staging.example` قوالب عامة فقط.
- الصورة لم تبن محليًا لأن Docker Engine غير متاح. فحص SIGTERM على Linux وصورة الحاوية ما زال مطلوبًا؛ نجاح اختبار إنهاء العملية على Windows لا يثبت مسار إشارات Linux.
- اختبار وصول حساب Railway بقراءة فقط أعاد `Not Authorized`. لم تستخدم أي mutation لإنشاء أو تعديل مشروع أو خدمة، ولم تنشر الحزمة.

حزمة المصدر المضغوطة في `verification/biometric-system-railway-staging.zip` مستبعدة من git والصورة وحزمة npm. سجلات الاختبارات وفحص الحزمة في `verification/`. القوالب لا تتضمن بيانات اعتماد TiDB أو TolanHR.

## المتبقي لإثبات النشر السحابي

1. توفير جلسة دخول صالحة إلى Railway واختيار مشروع أو بيئة تجربة مستقلة وخدمة جديدة.
2. بناء Dockerfile على Railway أو محرك Docker متاح، وفحص سجل البناء والإقلاع.
3. تطبيق إعدادات الخدمة الموثقة وإنشاء نطاق تجربة، ثم اختبار HTTPS والصحة ورفض الأجهزة وعدم إتاحة الإدارة.
4. تسجيل هوية الخدمة والنطاق ونتائج الفحوص الفعلية في الخطة. لا تعتبر صحة الخدمة دليلًا على استقبال جهاز أو قاعدة بيانات.

تشغيل الجهاز الحقيقي وربط قاعدة مستقلة واستخراج التاريخ والإدارة عن بعد تبقى أعمالًا لاحقة؛ هذه التجربة لا تفعّلها.
