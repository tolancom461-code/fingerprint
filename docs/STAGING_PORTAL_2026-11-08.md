# بوابة إدارة نظام البصمة التجريبية

تضيف هذه النسخة صفحة دخول ولوحة عربية مستقلة لعرض الأجهزة والأشخاص والحركات، واختبار صلاحيات مدير وحساب عرض فقط. تستخدم بيانات وهمية في ذاكرة العملية؛ لا تتصل بجهاز البصمة أو TiDB أو TolanHR، والتغييرات والجلسات تمسح عند إعادة تشغيل الخدمة.

## ما أنجزته البوابة

- صفحة دخول مستقلة دون كلمة مرور افتراضية.
- جلسة عشوائية داخل الخادم، في Cookie من نوع HttpOnly وSameSite=Strict، وSecure واسم يبدأ بـ`__Host-` على HTTPS.
- حساب مدير يستطيع إضافة شخص تجريبي، وحساب عرض اختياري يستطيع القراءة والخروج فقط. يتحقق الخادم من الصلاحية؛ إخفاء الزر في الواجهة ليس الحماية الوحيدة.
- عرض الأجهزة بوصفها غير متصلة، والأشخاص والحركات كبيانات تجريبية واضحة، مع بحث وصفحات وعرض متجاوب للجوال.
- تحقق Origin وCSRF لطلبات الكتابة والخروج، وحد لمحاولات الدخول وعمليات اشتقاق كلمات المرور المتزامنة وحجم الجلسات.

تبقى واجهة الإدارة المحلية القديمة ومسارات إعادة إصدار التاريخ محجوبة عن البوابة. لا توفر هذه النسخة تسجيل جهاز حقيقي أو سحب سجله القديم أو تعديل بيانات الإنتاج.

## رفع التحديث

ارفع التغييرات في مشروع `biometric-system` نفسه إلى مستودع GitHub المرتبط بخدمة التجربة، مع `Dockerfile` و`src/` و`scripts/` وملفات الحزم والتوثيق. تستبعد ملفات `.env` الفعلية و`verification/` و`var/` و`node_modules/` من الرفع.

أبق أمر التشغيل `node src/railway-staging.js`، والمنفذ `8080` وفحص الصحة `/health`. Dockerfile ينسخ ملفات واجهة البوابة وأداة توليد الهاش؛ لا يحتاج تثبيت مكتبات إضافية.

## إنشاء كلمة المرور

افتح PowerShell في مجلد المشروع:

```powershell
cd C:\Users\mh\Desktop\FINGER\Fingerprint\biometric-system
npm run admin:password-hash
```

أدخل كلمة مرور خاصة بك من 12 إلى 256 حرفًا وبحد أقصى 1024 بايت UTF-8. لا تظهر أثناء الكتابة؛ ينتج السكربت سطرًا يبدأ بـ`scrypt-v1$`. انسخ هذا السطر فقط إلى متغير الهاش. لا تكتب كلمة المرور في GitHub أو مثال الإعدادات أو سجل النشر، ولا ترسلها في المحادثة. اختر كلمة المرور الأصلية عند الدخول في المتصفح، وليس سطر الهاش.

الهاش مملح ويستخدم scrypt بمعاملات ثابتة `N=16384, r=8, p=5`، مع حد عمليتين متزامنتين. لا يقبل التكوين كلمة مرور صريحة مكان الهاش. أمثلة البحث الآمن والجلسات موثقة لدى [Node.js](https://nodejs.org/docs/latest-v22.x/api/crypto.html) و[OWASP لتخزين كلمات المرور](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) و[إدارة الجلسات](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).

## متغيرات Railway المطلوبة للتفعيل

المتغيران السابقان يبقيان كما هما:

```env
NODE_ENV=production
PORT=8080
```

أضف الأربعة التالية، مع استبدال قيمة الهاش بالناتج الفعلي واسم المستخدم بما تختاره:

```env
BIOMETRIC_STAGING_PORTAL_ENABLED=true
BIOMETRIC_STAGING_PORTAL_ORIGIN=https://fingerprint-production-c9df.up.railway.app
BIOMETRIC_STAGING_ADMIN_USERNAME=admin
BIOMETRIC_STAGING_ADMIN_PASSWORD_HASH=REPLACE_WITH_GENERATED_SCRYPT_HASH
```

اسم المستخدم من 3 إلى 80 حرفًا إنجليزيًا أو رقمًا أو الرموز `. _ @ -`. قيمة Origin هي أصل النطاق فقط دون مسار، ويجب أن تطابق النطاق الذي تفتحه. إذا تغير النطاق، يحدث Origin ليطابقه. لا تنسخ القيمة البديلة `REPLACE_WITH_GENERATED_SCRYPT_HASH` حرفيًا؛ ستفشل بداية التشغيل إذا كان التفعيل صحيحًا والإعداد غير صالح.

لحساب العرض، اختر كلمة مرور أخرى وشغل أداة الهاش مرة ثانية، ثم أضف القيمتين معًا:

```env
BIOMETRIC_STAGING_VIEWER_USERNAME=viewer
BIOMETRIC_STAGING_VIEWER_PASSWORD_HASH=REPLACE_WITH_ANOTHER_GENERATED_SCRYPT_HASH
```

لا يلزم متغير سر للجلسة: المعرّفات عشوائية ومحفوظة في ذاكرة الخادم، وتبطل بإعادة تشغيله. تستخدم التجربة نسخة تشغيل واحدة؛ تعدد النسخ يحتاج تخزين جلسات مشتركًا وتصميمًا آخر. لا تضف بيانات TiDB أو TolanHR إلى هذه التجربة.

## ما تتوقعه بعد النشر

1. `/health` يبقى 200 و`OK`.
2. الجذر `/` يحول غير المسجل إلى `/login`، ثم يعرض اللوحة بعد الدخول.
3. `/auth/session` و`/api/portal/*` يعيدان 401 دون جلسة.
4. المدير يستطيع إضافة كود يبدأ بـ`DEMO-` داخل ذاكرة التجربة، وحساب العرض لا يستطيع ذلك حتى بطلب مباشر إلى API.
5. الخروج يلغي الجلسة في الخادم. الجلسة تنتهي بعد ثماني ساعات كحد مطلق، وتبطل جميع الجلسات عند إعادة التشغيل.
6. طلبات جهاز البصمة تبقى مرفوضة؛ لا تغير إعداد Cloud Server داخل الجهاز بسبب تفعيل البوابة.

حد الدخول الافتراضي خمس محاولات خلال 15 دقيقة لكل عنوان اتصال وحساب، ويشمل المحاولات الناجحة. لا نعتمد على `X-Forwarded-For` غير موثق؛ قد تشترك زيارات Railway في حصة عنوان الوكيل. إذا بلغ الحد، انتظر انتهاء النافذة. هذه حماية محدودة للتجربة، وليست بديلًا عن تصميم وصول متعدد المستخدمين للإنتاج.

## إيقاف البوابة والتراجع

اضبط `BIOMETRIC_STAGING_PORTAL_ENABLED=false` وأعد النشر. تعود الخدمة إلى تجربة الصحة فقط وتختفي بوابة الدخول، دون تغيير القاعدة أو الجهاز. يمكن كذلك الرجوع إلى حزمة النشر السابقة. لا تتأثر النسخة الأصلية في مشروع TolanHR أو خدمة Windows.

المتبقي بعد هذه النسخة هو اختبار النشر الفعلي للبوابة، ثم استكمال بوابة حفظ البصمات القديمة وفصل القاعدة والربط. البيانات المعروضة هنا ليست نتيجة استرجاع لسجل الجهاز.
