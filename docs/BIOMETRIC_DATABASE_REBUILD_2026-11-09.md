# إعادة بناء قاعدة البصمة ونسخ الجداول الأصلية

التاريخ: 9 نوفمبر 2026. الحالة: **اكتملت إعادة إنشاء `fingerprint` واستعادة الجداول العشرة الأصلية والتحقق منها**. لم يفعل اتصال البرنامج أو الجهاز أو Railway على هذه النسخة بعد. بقي المصدر `test` للقراءة فقط طوال العمل.

## التنفيذ والنتيجة

بعد موافقة صاحب المشروع، حفظت نسخة كاملة لجداول الوجهة التجريبية ونسخة مستقلة لجداول البصمة الأصلية. صدرت كل نسخة بوقت TiDB ثابت واحد باستخدام SELECT AS OF TIMESTAMP، دون SET أو معاملة أو أقفال أو تغيير GC في المصدر. حفظت JSON كنص وBIGINT كنص ودقة الوقت وNULL، دون إعادة توليد مفاتيح أو UUID أو معالجة البيانات.

اختبرت استعادة النسختين في قاعدتي تحقق مؤقتتين جديدتين على TiDB. نجحت مقارنة محتوى الصفوف وبصماته والتعريفات والفهارس والعدادات، ثم حذفت قاعدتا التحقق فقط. بعد إعادة فحص الوجهة الحالية مقابل النسخة المحفوظة، حذفت `fingerprint` وأعيد إنشاؤها واستعيدت فيها جداول المصدر العشرة من النسخة المحلية. نجحت المطابقة ثم تحقق حساب القارئ مرة أخرى.

مطابقة المحتوى تمت لكل صف وكل عمود، إضافة إلى DDL الفعلي وON UPDATE وتعليقات TiDB ودقة التوقيت والعدادات الآمنة. لا تساوي هذه الأعداد بعضها لأن الجداول تمثل مراحل وروابط وحالات مختلفة. بقيت الحالات المعلقة وحقول UTC الفارغة كما كانت؛ لم ينفذ إصلاح أو إعادة معالجة أثناء النقل.

أداة النقل سجلت 55 أمر SELECT/SHOW على المصدر وصفر أوامر كتابة. أوامر الحذف المسجلة حصرت في `fingerprint` وقاعدتي التحقق الجديدتين المملوكتين للعمل. لم تعدل اليومية أو العمال أو الرواتب أو سجل استيراد TolanHR أو مؤشرات التسليم أو خدمة Windows أو إعداد الجهاز.

## النسخ المحفوظة والأدلة

المجلد المحلي `verification/biometric-migration-2026-11-09-O0DHCN/` يحتوي:

- `destination/`: جميع جداول التجربة السابقة وبياناتها وهوية الاختبار، لاستعادة الحالة السابقة عند الحاجة.
- `source/`: جداول البصمة العشرة وبياناتها الأصلية عند اللقطة الثابتة.
- داخل كل مجلد `manifest.json` يصف الأعمدة والتعريفات والأعداد وبصمات المحتوى، وملفات `*.rows.json` بترميز قيم لا يغير أنواعها.

هذه الملفات تحتوي بيانات حقيقية، وهي مستبعدة من Git وحزمة npm وصورة Docker. لا تعدّلها أو ترفعها مع مصدر المشروع. نجح اختبار الاستعادة الفعلي لكلتا النسختين قبل الحذف، ولم يحتج التنفيذ النهائي إلى rollback.

الأدلة المنقحة في `verification/biometric-migration-latest.json` و`verification/biometric-migration-summary-2026-11-09.json` و`verification/biometric-migration-audit-*.json` و`verification/biometric-migration-tests.log` و`verification/biometric-migration-original-code-comparison.json`.

الاختبارات **316/316** ناجحة، منها 30 جديدة لصيغة النسخ وحراسة DDL والتصدير بلقطة ثابتة والتحقق والاستعادة. بقيت ملفات الخدمة الأصلية الـ109 وملفات TolanHR الـ454 مطابقة للمرجع.

اجتازت حزمة مصدر من 235 ملفًا فحص الاستبعاد وفحص المحتوى دون بيانات النسخ أو تقاريرها أو ملفات الاعتماد أو كلمات المرور. يرفض أمر النقل تشغيل نسخة جديدة فوق سجل موجود؛ اختبر الرفض بعد الإتمام دون اتصال قاعدة أو تغيير السجل المكتمل.

## الحالة التشغيلية وما بقي

الوجهة تشمل الجداول العشرة الحقيقية فقط. حذفت بيانات fixture وجدول `biometric_portal_test_identity` مع قاعدة التجربة، ولم يعاد إنشاؤهما. مدخل `test-portal` التجريبي الحالي يطلب ذلك الجدول، لذلك لا يعتمد لتشغيل النسخة الحقيقية بمتغيراته القديمة وحدها. لم يتجاوز حارس الهوية أو تفعل كتابة تشغيلية أو إدارة عامة ضمن النقل.

البيانات تمثل وقت اللقطة `2026-11-09 10:59:22.326167` بتوقيت جلسة المصدر. المصدر ما زال يعمل مستقلًا؛ الإضافات والتحديثات بعد اللقطة تحتاج مصالحة لاحقة قبل التحويل. هذه ليست مزامنة مستمرة ولا تنزيلًا للتاريخ الموجود على الجهاز وحده.

متابعة لاحقة في اليوم نفسه: جهز واختبر اتصال بوابة القراءة الحقيقية على TiDB بحساب SELECT محدود، دون marker تجريبي أو تعديل بيانات. دليل [بوابة القاعدة المستقلة](STANDALONE_DATABASE_PORTAL_2026-11-09.md) يسجل النتائج وإعدادات النشر. يبقى تفعيلها على Railway ومراجعة ما بعد اللقطة وحالة Web Bridge ومؤشر TolanHR قبل أي تحويل جهاز أو تسليم حركات. يظل المصدر ممنوع الكتابة من أدوات هذا العمل.
