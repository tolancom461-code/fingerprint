# نظام البصمة المستقل

نسخة مصدر مستقلة من `tolan-biometric-service` بالإصدار `0.18.0`، مستخرجة من `finger/biometric-service` بتاريخ 8 نوفمبر 2026. تدير الخدمة الأجهزة والأشخاص وحركات البصمة وتنتج أحداثًا قابلة لربط البرامج الخارجية. يبقى حساب الحضور والورديات والرواتب داخل كل برنامج مستهلك، مثل TolanHR.

بدأ المشروع باستخراج مصدر مستقل؛ ثم أضيف مدخل تجربة Railway وبوابة إدارة اختيارية موثقان أدناه. لم يتحول جهاز الإنتاج أو خدمة Windows أو قاعدة البيانات إلى هذا المجلد، والمصدر التشغيلي السابق محفوظ في مكانه.

أضيف إعداد نشر تجريبي مستقل على Railway بمدخل تشغيل منفصل يختبر الخدمة فقط، ويعطل استقبال الأجهزة وقاعدة البيانات والإدارة والتوصيل بصورة مفروضة. راجع [دليل نشر Railway التجريبي](docs/RAILWAY_STAGING_DEPLOYMENT_2026-11-08.md). لا يعني تجهيز الملفات أن النشر على الحساب أو ربط الجهاز قد تم.

تتوفر الآن [بوابة إدارة تجريبية محمية](docs/STAGING_PORTAL_2026-11-08.md) تُفعّل بمتغيرات مستقلة بعد توليد كلمة مرور خاصة بك. تعرض أجهزة  وأشخاصًا وحركات وهمية فقط، وتدعم مديرًا وحساب عرض اختياريًا. تبقى الإدارة المحلية القديمة وAPI الأحداث واستقبال الأجهزة وقاعدة الإنتاج معطلة في وضع Railway التجريبي.

نتيجة التجهيز والفحوص وما بقي قبل إثبات النشر السحابي في [سجل تجهيز التجربة](docs/RAILWAY_STAGING_PREPARATION_STATUS_2026-11-08.md).

جهز أيضًا [مسار قراءة محمي من بيانات الخدمة](docs/PHASE1_STEP1_READ_ONLY_PORTAL_2026-11-09.md)، ثم أضيف [مدخل تشغيل من قاعدة اختبار معزولة](docs/PHASE1_STEP2_TEST_DATABASE_2026-11-09.md) بأمر `npm run start:portal-test`. لا يغير هذا مدخل Railway الافتراضي أو يحول بيانات الإنتاج؛ نتائج التحقق وحدوده موثقة في دليل الخطوة الثانية.

جهزت أولًا [قاعدة TiDB للتجربة](docs/TIDB_TEST_SETUP_2026-11-09.md)، ثم استبدلت وفق موافقة صاحب المشروع بـ[نسخة جداول البصمة الأصلية العشرة](docs/BIOMETRIC_DATABASE_REBUILD_2026-11-09.md) بعد حفظ النسخ واختبار استعادتها. لا تشمل النسخة الجديدة هوية fixture، ولا يشغل عليها مدخل `test-portal` القديم.

أضيفت [بوابة قراءة من القاعدة المستقلة الحقيقية](docs/STANDALONE_DATABASE_PORTAL_2026-11-09.md) بحساب SELECT محدود، واختبرت محليًا ثم على نطاق Railway العام بتاريخ 9 نوفمبر 2026: جهاز واحد و5 أشخاص و33 حركة نهائية، مع نجاح الجاهزية والدخول والقوائم. مدخل Docker الحالي `src/railway.js` يبقى demo افتراضيًا، والنشر العام الحالي يشغل القراءة بـ`BIOMETRIC_RAILWAY_MODE=database-readonly`. استقبال الجهاز والإرسال إلى البرامج الأخرى غير متاحين في مدخل القراءة؛ حفظ تاريخ الجهاز وتحضير الاستقبال والمصالحة والتسليم متطلبات المتابعة.

اختبر أيضًا [مسار الاستقبال المستقل](docs/PHASE1_DEVICE_INGEST_ACCEPTANCE_2026-11-09.md) بمدخل `src/index.js` الحقيقي وMySQL محلي جديد وبيانات مصطنعة: اجتاز 13 فحصًا فعليًا. أصلحت أهلية المعالجة التلقائية لتبقى السجلات المخزنة القديمة خارجها مع تعافي الحركات الجديدة بعد التوقف. أضيف عمود الأهلية لاحقًا إلى وجهة TiDB بعد نسخة حديثة وفحص جميع قيم الأعمدة القديمة؛ لا تحتاج بوابة القراءة هذا العمود.

جهز الآن [وضع الاستقبال السحابي والحفظ](docs/CLOUD_INGEST_DEPLOYMENT_2026-11-09.md) `database-ingest`، بحساب كاتب محدود ومصادقة آلة وقائمتي الحركات المستلمة ومستخدمي الأجهزة. اجتاز 9 فحوص حفظ فعلية على MySQL و6 فحوص قراءة للمدخل الجديد على TiDB، والحزمة 406 اختبارات. ملف Variables كامل جاهز محليًا؛ لم يفعل الوضع الجديد على Railway بعد، ولم يغير اتصال الجهاز. يبدأ دون اعتماد نهائي تلقائي أو توصيل إلى TolanHR، وتظل قناة الجهاز المصادق عليها وحفظ تاريخه واختباره الفعلي مفتوحة.

## التثبيت والتحقق

المتطلب: Node.js بإصدار يحقق `engines` في `package.json`، وnpm. يستخدم أمر التشغيل الصريح أدناه ميزة `--env-file` التي تتطلب Node.js 20.6 أو أحدث.

```powershell
npm ci --ignore-scripts --no-audit --no-fund
npm test
npm run check:boundaries
```

لاختبار الاستقبال المعزول على Windows حيث يتوفر MySQL Server: `npm run verify:ingest-mysql`. ينشئ هذا الأمر مختبرًا جديدًا على loopback بمنافذ مؤقتة وبيانات مصطنعة، ثم يوقف عملياته المملوكة؛ لا يستخدم قاعدة TiDB أو أجهزة حقيقية أو خدمة Windows القائمة.

لا تحتاج الاختبارات إلى إعداد اتصال بقاعدة الإنتاج. تثبيت الحزم يعتمد على `package-lock.json` المنقول كما هو من المصدر.

## إعداد التشغيل

انسخ `.env.example` إلى ملف `.env` محلي، واضبط إعدادات قاعدة مخصصة للاختبار والأجهزة المسموح بها. ملف المثال ليس إعداد إنتاج جاهزًا؛ لا تعِد استخدام أسرار TolanHR. إعدادات قاعدة البيانات مطلوبة في وضع `database`، ويتحقق بدء التشغيل من المخطط دون إنشاء أو حذف جداول تلقائيًا.

بعد تجهيز القاعدة والإعدادات، يمكن تشغيل الخدمة صراحةً:

```powershell
node --env-file=.env src/index.js
```

الأمر `npm start` الحالي يشغل `node src/index.js`، ويتوقع وجود الإعدادات في بيئة العملية مسبقًا؛ لا يقرأ `.env` تلقائيًا. لم يغيّر الاستخراج هذا السلوك.

لا تشغل نسخة ثانية ككاتب إنتاج إلى جانب الخدمة الحالية. التشغيل التجريبي يحتاج قاعدة معزولة ومنافذ غير متعارضة، ويجب ألا يوجّه أحداث التجربة إلى TolanHR الإنتاجي.

## حدود النسخة الحالية

- مستقبل ADMS يستخدم المنفذ `9095` افتراضيًا؛ الإدارة `9096` وواجهة قراءة الأحداث `9097` مقيدتان بـloopback.
- النشر العام والإدارة عن بعد يحتاجان تصميم وصول وTLS ومصادقة واختبار توافق الجهاز؛ هذا الاستخراج لا يفعلهما تلقائيًا.
- موصل Web Bridge اختياري ويدعم وجهة واحدة بصيغته الحالية. عقد قراءة Final Events محايد ويمكن بناء مستهلك مستقل عليه.
- حالة التسليم والسجلات المحلية تتولد في `var/` أثناء التشغيل، وتحتاج حفظًا دائمًا عند تصميم النشر. لم تنقل بيانات تشغيل فعلية إلى هذا المشروع.
- إعادة معالجة التاريخ الموجودة في الخدمة ليست أداة تنزيل كامل سجل جهاز البصمة. حفظ الحركات القديمة واستخراجها ونقل القاعدة أعمال لاحقة موثقة في خطة الفصل.
